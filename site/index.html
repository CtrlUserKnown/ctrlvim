> Neovim's core, rewritten in Rust. Same modes, same motions, zero C.
ctrlvim is a from-scratch Rust reimplementation of Neovim's editing
engine — rope buffers, the mode state machine, the ex-command layer,
a Lua runtime — with a Ratatui-powered terminal frontend on top.
╭─────────────────────────────────────────────╮
│ 13 crates · 176 tests · zero C · Apache-2.0 │
╰─────────────────────────────────────────────╯

# Workspace architecture
13 crates, strict dependency direction, no global mutable state.
types ─▶ text ─▶ options ─▶ editor ─▶ vimscript ─▶ api ─▶ lua ─▶ core ─▶ tui
## Crates
ctrlvim-types dynamic Object, arena handles, Position/Range, errors
└ replaces object / typval, handles
ctrlvim-text rope-backed Buffer, MarkStore, UndoTree, Registers
└ replaces memline.c mark.c undo.c register.c
ctrlvim-options three-tier global / buffer / window overrides
└ replaces option.c + options.lua
ctrlvim-editor motions, operators, Mode machine, Session dispatch
└ replaces normal.c ops.c textobject.c edit.c state.c
ctrlvim-vimscript minimal Vimscript interpreter with builtins
└ replaces eval.c + eval/*.c
ctrlvim-treesitter parse, query, node ranges, highlight spans
└ replaces lua/treesitter.c
ctrlvim-api ApiContext, #[ctrlvim_api] functions, autocmd store
└ replaces src/nvim/api/*.c
ctrlvim-lua mlua embedding, Object ↔ Lua converter, vim.* bridges
└ replaces executor.c converter.c
ctrlvim-async Tokio event loop, timers, jobs, msgpack-RPC codec
└ replaces event/*.c msgpack_rpc/*.c
ctrlvim-core the Ctrlvim facade, scripting bridge, demo binary
└ replaces startup wiring
ctrlvim-tui Ratatui + crossterm frontend
└ replaces (the UI, split out)
## Design principles
╭──────────────────────────────────────────────────────────────────╮
│ No global state. Everything threads through an explicit Editor │
│ with copyable integer handles — a stale handle is a clean None. │
│ │
│ One callback mechanism. Autocmds, keymaps and timers all store │
│ an Object::LuaRef resolved through the same registry. │
│ │
│ Codegen via proc-macro. #[ctrlvim_api] on a Rust fn emits both │
│ Lua and RPC dispatch — no C-text parser needed. │
│ │
│ Engine first. Editor logic lives in the engine behind a host- │
│ effect boundary; the TUI only draws and forwards keys. │
╰──────────────────────────────────────────────────────────────────╯

# Inline AI suggestions
> Ghost text ahead of the cursor, from a model on your own machine.
CodeGemma-2B on candle, in-process. No API key, no network at edit
time, nothing leaving the machine. It is fill-in-the-middle, so the
model sees the code on both sides of the cursor:
<|fim_prefix|>code before<|fim_suffix|>code after<|fim_middle|>
## Two switches, and both start off
1. Build it in. The backend is not compiled unless you ask:
$ cargo build -p ctrlvim --release --features ai
candle is minutes of compile time, so a stock build does not pay for
it. Without the feature the commands still answer — suggestions just
report that the backend is absent, rather than silently never coming.
2. Switch it on. Still off even in a build that has it, because
the first suggestion downloads weights. Three ways:
Settings tab Dashboard → settings → Inline AI suggestions.
The persistent one: writes back to config.toml.
:AI on this session only
config.toml [ai] enabled = true
## Keys
Ghost text only claims keys while it is on screen. With nothing
suggested, Tab inserts a tab and ^E does what it always did.
⇥ accept the whole suggestion
^L accept one word, keep the rest
^J accept one line, keep the rest
^E dismiss it, stay in Insert
Esc leave Insert; the suggestion goes with it
## Commands
:AI toggle (:AI on / :AI off to be explicit)
:AISuggest complete at the cursor now, skip the idle delay
:AIStatus where the model is — or why it failed
:AILoad load the weights now, not on first use
The status line carries a marker while suggestions are armed:
AI ready · AI ↓ loading · AI … thinking · AI ! failed
## Be realistic about speed
Measured on a 4-core laptop, quantized, ~20 lines of context:
╭──────────────────────────────────────────────────────╮
│ Prompt prefill (~200 tokens) ~35 s │
│ Each generated token ~0.45 s │
│ Model load (cached weights) a few seconds │
╰──────────────────────────────────────────────────────╯
Prefill dominates, and it scales with the context you send — which
is why context_before defaults to 20 lines rather than something
generous. Doubling it roughly doubles time-to-first-suggestion.
In order of effect, if that is too slow:
1 build with GPU support — --features ai-cuda / ai-metal
2 build in release at all (debug cannot finish one)
3 shrink the context (context_before = 10)
4 lower max_tokens — you rarely accept more than a line
## Why it doesn't drag the editor down
Inference is confined to cores - 1 threads. candle parallelizes
across every core it finds, and a 2B model keeps them all busy for
seconds — which made the whole editor feel slow, not just the
suggestions. One core left for the UI buys that back.
The rest is unchanged: a completion is asked for only once typing
pauses, only one is ever in flight, and a newer request abandons the
older one mid-token.
## Disk and memory
A 4-bit quantized GGUF by default — the same 1.63 GB file Ollama's
codegemma:2b tag ships. Full-precision safetensors are 5.01 GB and
load only with gguf = "".
Resident memory is ~2.8 GB: the weights plus a 1.05 GB f16
embedding table — Gemma's vocabulary is 256,000 tokens, so that table
is large however hard the weights are quantized.
Gemma-2, Gemma-3 and Llama GGUFs will not load: this is a Gemma-1
decoder, written because candle-transformers ships no Gemma-1.

# ctrlvim is configured in TOML, not in a config script.
#
# TOML expresses the *wiring* — options, mappings, event bindings,
# plugins. Anything needing actual logic lives in a plugin, which this
# file then refers to by name. The bridge is the Ex command: a keymap's
# rhs and an autocmd's command are ordinary `:` commands, so a plugin
# contributes behaviour by registering :Format and the config names it.
#
# Lives at ~/.config/ctrlvim/config.toml
# The editor shell itself.
[ui]
drawer = false # file drawer (^B) open on startup
mouse = true # off gives the wheel back to the terminal
icons = "auto" # auto | nerd | text
theme = "Tokyo Night" # or Terminal, Catppuccin, Noir-cat,
# Rosé Pine, Gruvbox, Habamax
# Anything `:set` understands. Untyped on purpose: every option the
# engine gains works here immediately. `true` sets it, `false` becomes
# the no- form, numbers and strings become name=value.
[options]
number = true
relativenumber = true
ignorecase = true
smartcase = true
expandtab = true
tabstop = 4
shiftwidth = 4
scrolloff = 5
foldmethod = "indent"
timeoutlen = 500 # how long a half-typed chord waits, and
# when the which-key popup appears
[keymaps]
defaults = true # false starts from an empty table
leader = " " # applies at definition time, as in Vim
# One table per mapping. `mode` is "n" (default), "i" or "v"; both
# sides use <...> notation. `desc` is what ? and which-key show — the
# difference between a keymap you can discover and one you can't.
# An lhs that doesn't parse is reported, never silently dropped.
[[keymap]]
lhs = "<leader>g"
rhs = ":Find<CR>"
desc = "Search the project"
[[keymap]]
mode = "i"
lhs = "jj"
rhs = "<Esc>"
desc = "Leave Insert mode"
# [[unmap]] removes a built-in chord entirely, so the key falls back
# to its Vim meaning. Rebinding the same lhs already replaces it.
# Define a `:` command as an alias for another. This is the escape
# hatch that keeps the config declarative — a [[command]] plus a
# [[keymap]] pointing at it is a complete binding, no plugin involved.
#
# In a filename position, % expands with Vim's modifiers: %:p full
# path, %:h dir, %:t name, %:r no extension. They chain (%:t:r).
# Elsewhere % is left alone, so :s/50%/half/ still works.
[[command]]
name = "RunPython"
expansion = "!python3 %:p"
# Run an Ex command when an event fires. `pattern` matches the
# buffer's name: "*", "*.rs", "test_*", or an exact name.
# Events: VimEnter, BufEnter, BufLeave, BufWritePre, BufWritePost.
[[autocmd]]
event = "BufWritePre"
pattern = "*.rs"
command = "set expandtab"
# A directory holding an init.lua or init.vim. Load order is the order
# declared here — what loads, and when, is explicit rather than
# emergent, which is why there is no runtimepath search.
[[plugin]]
name = "example"
path = "~/.config/ctrlvim/pack/example"
event = "BufWritePre" # omit to load at startup
# Inline AI suggestions — see the ai.md buffer. Needs --features ai at
# build time, or this section has nothing to switch on.
[ai]
enabled = true
device = "auto" # auto | cpu | cuda | cuda:1 | metal
debounce_ms = 350 # idle time before a completion is asked for
context_before = 20 # lines before the cursor — the prefill cost
context_after = 6
max_lines = 8 # ghost-text rows to show (1 = strictly inline)
